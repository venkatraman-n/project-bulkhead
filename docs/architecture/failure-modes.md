# Failure modes

| # | Failure | Detection | System behaviour | Bank impact | Covered by |
|---|---|---|---|---|---|
| F1 | Redis slow (responses beyond the remaining budget) | Feature lookup exceeds its deadline-derived timeout; breaker failure rate | Velocity and new-beneficiary rules skipped; tenant degradation policy applied; response `degraded: true` + `missingFeatures` | Answer still inside budget; decision per the bank's own policy | src/test/java/com/azentio/bulkhead/screening/DegradedScoringTest.java (500 ms slow store), src/test/java/com/azentio/bulkhead/features/ResilientFeatureClientTest.java; ADR 0004 |
| F2 | Redis down / flapping | Connection errors; breaker opens | Breaker short-circuits calls (no wait); same degraded path as F1; half-open probes on recovery | Same as F1, without paying the timeout on every request | src/test/java/com/azentio/bulkhead/features/ResilientFeatureClientTest.java (opens, short-circuits, closes); src/test/java/com/azentio/bulkhead/features/RedisDegradationIntegrationTest.java (real Redis paused, `-Pintegration`) |
| F3 | PostgreSQL slow or down | Connection refused; Hikari acquire timeout (250 ms, its minimum); `statement_timeout` 50 ms on PostgreSQL | Fail closed: 503 `SYSTEM_OF_RECORD_UNAVAILABLE`, no unrecorded decision. **Limit:** a slow pool can take up to 250 ms, beyond the 80 ms budget, so the switch's own timeout may fire first | Switch applies its own fallback; retry later is safe (idempotent) | src/test/java/com/azentio/bulkhead/screening/SystemOfRecordFailureTest.java proves the 503 mapping only. Slow-DB timing not yet covered: needs DB-latency fault injection and a deadline-derived DB timeout |
| F4 | Concurrent retry of the same transaction (any instance) | Claim insert on `screening_claim` primary key fails | Only the claim owner scores; duplicates wait for its committed decision; a different payload gets 409 before touching features | Identical answer to every retry; scored once; nothing counted twice | src/test/java/com/azentio/bulkhead/screening/ConcurrentIdempotencyTest.java |
| F5 | Same transactionId reused with a different payload | Stored payload hash differs | 409 `IDEMPOTENCY_CONFLICT`; original decision untouched | Switch bug surfaced explicitly | src/test/java/com/azentio/bulkhead/screening/IdempotencyApiTest.java |
| F6 | Bad tenant config (invalid values, zero/over-long velocity window, unreadable file) | Validation at startup, ERROR log naming the tenant | Only that tenant disabled: 503 `TENANT_CONFIG_INVALID`; other tenants score normally | Affected bank uses its fallback until the file is fixed; others unaffected | src/test/java/com/azentio/bulkhead/tenant/TenantOnboardingTest.java |
| F7 | Unknown tenant id | No rule pack loaded for the id | 404 `UNKNOWN_TENANT` | Misrouted caller is rejected | src/test/java/com/azentio/bulkhead/screening/RulesApiTest.java |
| F8 | Instance crashes after commit, before the response | Switch times out and retries | Retry hits the idempotency fast path and returns the stored decision | No double scoring or counting | src/test/java/com/azentio/bulkhead/screening/IdempotencyApiTest.java |
| F9 | One bank's traffic spike (noisy neighbour) exhausts shared threads/connections | Per-tenant latency and in-flight metrics | Today: shared pools, so other banks slow down too | Other banks may miss their budget | Not yet covered: per-tenant bulkheads (semaphores per tenant) are a stretch goal; limits to go in nfr.md |
| F10 | Velocity counts after a Redis outage | `degraded = true` rows in the system of record | Transactions scored during the outage are not in velocity history; never double counted (`ZADD NX` by transactionId) | Undercount bounded by the tenant's longest window ([ADR 0004](adr/0004-degradation-and-recovery.md)) | src/test/java/com/azentio/bulkhead/features/OutageRecoveryTest.java |
| F11 | Future-dated transaction (switch clock wrong) | `timestamp` more than 5 min ahead of server time | 400 `TIMESTAMP_IN_FUTURE`; it would otherwise prune current velocity history | Bad request surfaced; velocity counts stay correct | src/test/java/com/azentio/bulkhead/screening/RulesApiTest.java |
